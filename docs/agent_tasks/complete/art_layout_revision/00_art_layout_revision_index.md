# 战斗界面布局美术升级总控

## 状态与依据

- 状态：已批准实施。
- 依据：`docs/art-layout-revision.md`、M4 当前场景与 `tests/artifacts/m4` 运行截图。
- 范围：只调整 `ui/`、`scenes/`、必要 InputMap 与视觉测试；不修改 Controller、VM、表现事件合同、战斗规则、队列时钟或忙锁语义。

## 合理性决议

1. 接受 A1、A2、A3、A5、A6 与 B1～B5。
2. 接受 A4 的 150×210 卡面、最小安全可见宽度、整体缩放、上下边界和 hover/drag 要求。
3. 不采用 A4 的“左压右并反转子节点顺序”：该顺序会遮住右侧卡牌的左侧安全区，与“每张卡左侧 108px 完整可见”冲突。正常态保持右侧后牌覆盖前牌右缘，hover/drag 单独置顶；名称、费用、类别必须留在可见安全区。
4. A1 的 HandLayer 使用 MainStack 内叠层，而不是作为 VBox 的普通高度子项，保证手牌不参与纵向高度分配。
5. 日志抽屉默认 `visible = false`，关闭时退出布局；打开时允许 MainRow 重新分配宽度，抽屉内容做 0.18 秒右侧滑入/滑出，动画不接入表现队列、不改变战斗输入锁。
6. B3 的“图标”首期实现为一致的短标签节点（抽/手/弃/耗）与数字，不引入 emoji 或临时新美术。
7. P2 全部保留不做：共享 Theme、全局字阶、色调重定、敌方立绘补齐与统一裁切留到第二期。

## 节点与视觉约束

- 正式动态视觉继续由 `.tscn` / `PackedScene.instantiate()` 创建。
- 渐隐底色使用场景内 `GradientTexture2D + TextureRect`；禁止 `_draw`、`draw_*` 或大量 `Control.new()`。
- 不以颜色作为唯一状态：阵亡需灰化并有场景节点标记；日志未读需数字角标；不可用仍保留文字原因。
- 控件最小点击区按现有 1200×700 桌面战斗界面保持不小于 44×44；结束回合不小于 120×44。
- 微交互控制在 0.12～0.18 秒；不得让抽屉动画阻塞卡牌、队列或倍速。

## 批次与顺序

1. ART-1：根骨架、双列棋盘/弈者面板、手牌叠层。
2. ART-2 与 ART-3 在 ART-1 通过后并行：
   - ART-2：手牌、卡牌、棋子格、结果/fatal 组件。
   - ART-3：顶栏 HUD 与日志抽屉。
3. ART-4：整合、三档窗口、八张证据与回归。
4. ART_LAYOUT_FINAL：独立代码可行性与阻塞级视觉 Review。

## 总完成条件

- 1200×700、1280×720、1600×900 均无明显溢出、裁切或死空洞。
- 日志默认隐藏，Tab/L 与按钮同入口；未读角标和自动滚底可验证。
- 0 张手牌无底框；7 张卡名/费用可读，旋转外接框不越界；hover/drag 不重排邻牌。
- 双方棋盘镜像，弈者面板随人数自适应并贴在所属棋盘上方。
- M4 行为回归、布局聚焦、图形 smoke 通过；不运行 1000 场回归。
