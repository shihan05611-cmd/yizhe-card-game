# M4-5 表现队列、飘字与倍速整合

## 目标

将 M4-2/3/4 接入同一个串行表现队列，完成棋子动作、Buff 批次、伤害/治疗飘字、血条分段变化和 1x–4x 倍速；确保逻辑只结算一次且表现期间不重入。

## 允许范围

- `app/**` 的表现调度增补
- `scenes/main.tscn` 与 M4 场景间的首次统一组合
- `ui/battle/**`、`ui/cards/**`、`ui/effects/**` 的集成接线
- `scenes/battle/**`、`scenes/cards/**`、`scenes/effects/**` 的必要接口修正
- 本批集成测试与 `docs/parity-checklist.md`

## 禁止范围

- 不改变 M2/M3 结算顺序和玩法结果。
- 不让动画回调再次调用伤害/技能结算。
- 不用 wall-clock 定时器决定领域成功与否。
- 不做自动战斗策略或 M5/M6。

## 依赖

- M4-2、M4-3、M4-4 完成，且各自测试通过。

## 实现要求

1. 一个命令对应一个稳定表现批次；事件按 sequence 串行消费，消费完成后才解除输入锁。
2. 逻辑 Command 可同步提交，但 UI 必须用事件快照按序表现；不得从动画节点反写权威状态。
3. 棋子行动/打击、Buff 同批刷新、遗物独立来源、卡牌去向、伤害/治疗与终局均有明确消费者。
4. DamageFloat、HealFloat、Block/Crit 标记等由预置节点场景实例化并自动回收。
5. 血条使用事件 old/new HP 或状态快照做 Tween，最终值必须与权威 VM 一致。
6. 速度只允许 1/2/3/4；所有队列 wait、Tween 和 FX clock 统一除以速度，逻辑事件数量与顺序不变。
7. 切换倍速不重复或跳过当前事件；最迟从下一调度段生效，并有明确测试口径。

## 完成条件

- `card_queue_presentation_test.gd` 验证重复输入锁、同一逻辑只提交一次、1x/4x 最终状态和事件序列相同、时长近似 4:1。
- `combat_presentation_integration_test.gd` 覆盖 W-021–W-024、伤害/治疗/Buff/遗物来源和终局。
- 7 张手牌在队列播放期间不被错误重复实例化或丢失。
- M4 聚焦与常规非稳定性回归通过；不运行 1000 场回归。
- 回报修改、测试、时长测量和风险，不自行验收或提交。
