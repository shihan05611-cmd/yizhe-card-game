# M4-6 自动战斗、完整闭环与图形证据

## 目标

完成自动战斗、主场景启动、从开始到胜负的完整可操作闭环，并生成 M4 的同窗口图形证据与交接材料。

## 允许范围

- `app/**`、`autoload/**` 的最终 M4 接线
- `scenes/main.tscn`、M4 场景与 UI 的最终集成
- `project.godot` 主场景和必要输入映射
- `tests/**` 的 M4 聚焦 runner、图形 smoke/capture
- `docs/parity-checklist.md`、`docs/m4-handoff.md`

## 禁止范围

- 不实现 M5/M6，不写存档，不调平衡数值。
- 不做最终美术精修。
- 不运行 1000 场回归。
- 不在自动战斗中绕过 HandManager/Command 或直接修改牌区/战斗状态。

## 依赖

- M4-5 完成并通过集成测试。

## 实现要求

1. `project.godot` 启动进入可操作演示战斗，不需要控制台或调试命令。
2. 自动战斗只消费权威可用性 VM，串行发出卡牌 Command；无可用牌时结束回合。对回手牌/拒绝结果有明确推进规则，不能死循环。
3. 自动战斗和手动输入共用同一 Command/表现队列；队列忙时不并发提交。
4. 战斗胜负后显示结果并停止自动战斗；fatal 状态显示原因并要求显式重开。
5. 提供 M4 聚焦 runner；常规 runner 继续明确省略 1000 场稳定性测试。
6. 图形证据至少包含同一 1200×700 窗口下：完整战斗 UI、7 张手牌、悬停、拖拽状态、1x 与 4x 同 seed/同动作、胜负结果。
7. 图形检查只要求无缺失、不可读、明显遮挡/溢出和错误状态；细节交给用户后调。

## 完成条件

- 手动可完成一场战斗，全程无需控制台。
- 自动战斗可从初始状态推进到 win/lose，无重入、无卡死。
- 1x–4x 四档可切换，4x 不丢结算。
- 7 张手牌不越界。
- `scene_instantiation_test.gd` 确认正式视觉节点来自场景实例化，并禁止即时绘制模式。
- M4 聚焦、常规非稳定性回归、图形 smoke 均通过并记录证据。
- `docs/m4-handoff.md` 记录接口、测试数字、图形证据、未决视觉细节和 M5/M6 边界。
- 回报后停止，交给 `M4_FINAL` 独立 Review；不自行验收或提交。
