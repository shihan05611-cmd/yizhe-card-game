## 冻结事务顺序

玩家成功出牌统一经过：

1. 解析卡牌实例与静态定义。
2. 检查队列状态、牌是否在手、目标/条件 validator、所有可在提交前验证的效果前置条件。
3. 计算 `effective_cost`/`actual_cost` 并验证 SP 足够。
4. 原子支付实际 SP，进入已提交阶段。
5. 通过 M2 EffectRegistry/既有入口精确结算一次效果；卡牌层不得重复伤害计算。
6. 按特殊返回手牌 > 消耗 > 默认弃牌决定成功去向，并记录“一局一次”等成功标志。
7. 发出稳定的卡牌成功事件，并按 `actual_cost` 结算玩家能量。
8. 每次玩家能量变化都立即检查满阈值；满能瞬间生成大招卡并清零对应弈者能量。

validator/preflight 失败发生在提交前：SP、牌区、成功次数、能量和战斗状态全部不变。若既有效果在已提交后报告失败，返回显式 committed-prefix/fatal 结果并停止当前队列；不得伪造回滚、把卡塞回原位后自动重试或重复调用效果。

## 明确玩法规则

- 自由技不选择施法者，效果只执行一次，玩法归属为全体上阵弈者。
- 上述自由技规则不包含已由 Q8 暂时移除的 `basicDamage` 卡；该 ID 不得通过目录、手牌或直接构造请求进入玩家桥。
- 主动专属技从 `owner_hero_id` 唯一推导所属弈者；调用者不能另传冲突 owner。
- 自由技成功：每名上阵弈者获得 `5 + actual_cost * 5` 能量。
- 专属技成功：仅 owner 获得 `10 + actual_cost * 10` 能量。
- 减费/免费均按实付 SP；0 SP 时仍分别获得 5/10 基础能量。
- 大招卡固定 0 SP、成功后消耗、不回复能量。
- 满能瞬间生成大招卡并先清零能量；手牌未满直接入手，满手则插入抽牌堆顶，且不计入正常 `2+N` 抽牌数。
- 同一个能量事件跨过多个阈值时，首版只按当前上限触发一次卡并清零，不在一次事件内循环生成多张。
- 影狩【潜影】成功后返回手牌；同回合不设置额外次数限制，仍受 SP 与 validator 限制。
- 骑士【反击】是被动，不生成专属技卡；其反击导致的玩家能量变化也必须经过统一满能检查。
- 玩家没有“每弈者行动一次”或“每回合出牌额度”；只要 SP/条件允许即可连续出牌，结束回合由显式命令触发。
