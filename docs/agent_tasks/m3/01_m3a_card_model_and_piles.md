## 目标

## 冻结接口与规则

1. `CardDefinition` 是静态数据，至少能表达卡牌来源、类别、基础费用、owner、默认去向/消耗与效果引用；不复制既有技能效果数值。
   - Q8 决议：卡牌目录必须排除自由技 `basicDamage`。只排除卡牌暴露，不删除或改写 M1/M2 的底层技能定义与 handler。
2. `CardInstance` 是运行时实体，必须包含唯一且确定可追踪的 `instance_id` 与 `source_skill_id`。两张同技能卡不得共享实例身份。
3. 运行时至少维护 draw/hand/discard/exhaust 四区；状态变更通过单一 API，不允许调用者直接改数组绕过规则。
4. 手牌上限固定为 7。到达上限时该次抽牌失败，原牌保持在抽牌堆顶，不补抽、不静默弃置。
5. 抽牌堆不足时将弃牌堆确定性重洗后继续；消耗堆不参与重洗。
6. 每回合抽牌 API 表达“新增抽 N 张”，不得实现成补至 N 张。`2+N` 的 N 由后续会话层传入，本批不读取战斗 roster。
7. 结束玩家回合时，仍在手中的普通卡进入弃牌堆；特殊成功去向由后续出牌事务决定，不在 end-turn 阶段二次搬运。
8. Q1/Q2：打出后“返回手牌”优先于默认消耗去向；“本局只能成功打出一次”只在成功结算后记账。此批只提供所需数据/状态 API，不伪造效果成功。
9. 命名 `deck` RNG 流必须从战斗 seed 确定性派生，且与 `combat`、`enemyPolicy` 消费顺序互不影响。
10. 队列一次只处理一个命令，拒绝或串行化重入；本批可用伪执行回调测试，不连接真实战斗效果。

## 实现要求

- 优先纯 GDScript `RefCounted`/值对象，使测试无需 SceneTree/Autoload 也能覆盖精确状态迁移。
- `HandManager` 不拥有第二套规则，只负责生命周期、信号或服务定位适配。
- 公共结果必须显式区分成功、validator/preflight 拒绝、牌堆耗尽/手牌已满等情况，避免以日志文本作为协议。
- 目录条目应由当前 M1 目录生成或引用；若发现现有数据缺少表达卡牌所需字段，只做最小、向后兼容扩展并加合同测试。
- 保证公共状态/trace 可被测试稳定比较；不要依赖 Dictionary 无序遍历决定抽牌或实例 ID。

## 必测清单

- 同技能多份卡具有不同 `instance_id`，且能追溯同一 `source_skill_id`。
- 卡牌目录与任何牌库构造入口均不会产出 `basicDamage` 卡，同时 M1/M2 既有定义与回归保持可用。
- 相同 seed + 相同初始牌序 → 首抽与多次重洗序列完全一致。
- 改变 deck 抽牌次数不改变 combat/enemyPolicy 随机结果，反之亦然。
- 新增抽牌而非补牌；传入 `2+N` 时精确尝试该数量。
- 手牌上限 7；满手抽牌失败且不补抽、不卡丢失。
- 抽牌堆空时仅重洗弃牌堆；消耗卡永不进入重洗。
- 回合结束普通手牌进入弃牌堆，四区总实例守恒。
- 返回手牌/消耗/弃牌的优先级 API 可表达且不产生重复实例。
- 被 validator 拒绝或队列忙时，四区、成功次数和 RNG 消费保持不变。
- HandManager 薄适配与纯 HandRuntime 给出一致结果。

至少覆盖 `hand_manager_test.gd` 中 R-012–R-015 对应命名测试，并补齐实例身份、独立 RNG 与队列边界测试。

聚焦 runner 不得重复纳入完整 RNG golden；只运行 deck 流隔离与同 seed/同牌库确定性牌序等卡牌层直接证据。不得因此删除共享 RNG 原测试。
