## 牌库组装规则

- 输入是明确的上阵弈者列表与自由技 ID 多重列表；相同自由技每出现一次就生成一个独立卡实例，不去重。
- Q8：即使外部自由技多重列表含 `basicDamage`，首版装配也必须显式拒绝该无效输入或过滤并返回结构化告警；不得静默生成该卡。具体采用“整次拒绝”或“过滤+告警”沿用 M3a 目录 API 的既有失败策略，不另造分支。
- 每名上阵弈者的主动专属技各加入一张；`owner_hero_id` 来自 M1 数据。
- 骑士【反击】不生成卡，但骑士仍计入 N。
- N 等于当前上阵弈者数量，首版每回合新增抽 `2+N` 张。
- 起始牌库依 Q6：开局弈者主动专属技各一张 + 初始自由技各一张；具体数量不在 M3 调平衡。
- 招募本身属于 M5。M3 只需证明当外部传入 roster/N 和自由技多重列表发生变化时，新战斗的牌库与抽牌数正确；不得实现购买/招募状态机。

## 回合与事件顺序

1. 战斗创建时验证输入、组装实例牌库、使用独立 deck RNG 洗牌，并按首回合规则新增抽 `2+N` 张。
2. 玩家通过 M3-2 桥连续出牌；没有 action quota。
3. 玩家显式结束回合后，先把仍在手中的普通卡送入弃牌堆，再进入 M2 `RoundResolver`。
4. M2 保持既有顺序：敌方弈者 → 双方 slot 1..6 棋子 → enemy/ally burn → finalize。
5. M2 结算中的玩家能量变化走统一满能检查。结算期间生成的大招卡保留在手牌；若手满则进 draw top。
6. 非终局 finalize 后清理真实的 M3 回合态，再为下一个玩家回合新增抽 `2+N` 张。
7. 已经生成的大招不计入正常抽牌额度；draw top 的大招被正常抽到时才占用一次实际抽牌尝试。
8. 终局不得继续抽牌或开启新玩家回合。

`RoundResolver` 的 `m3_obligations` 描述性占位必须被明确的会话职责取代或仅作为兼容 trace 保留且标记已履行；不得同时由两个层重复 reset/clear/resolve。

## 必测清单

- R-005：自由技 ID 多重列表中每一份都生成独立卡，允许同名重复。
- Q8：任何装配路径均不会产出 `basicDamage` 卡，并能观察到无效输入结果。
- R-006/R-017：主动专属技入起始牌库；骑士反击不入牌库但计入 N。
- R-012：首回合与后续回合均新增抽 `2+N`，不是补至目标手牌数。
- R-013–R-015：会话接线后仍满足上限、确定性重洗、end-turn 去向与实例守恒。
- 玩家手上留牌时结束回合：先弃手再 M2 结算；结算中新生成大招不会被刚才的弃手清掉。
- 满手生成的大招进 draw top；下一回合在抽牌尝试中按顺序取得，且生成动作本身不扣正常抽牌数。
- 完整循环：建局 → 抽牌 → 多次玩家出牌 → 主动结束 → M2 完整结算 → 下一轮抽牌。
- 终局停止后无额外抽牌、无重复 finalize、无悬挂队列。
- 同 seed/同输入的完整 trace 与牌序一致；改变 deck 操作不改变 M2 combat/enemyPolicy 结果。
- R-019：敌方旧规则与原有 M2 回合顺序回归通过。
- R-018 仅测试“外部输入改变后的新战斗装配”；不得将招募交易标成 M3 已完成。
