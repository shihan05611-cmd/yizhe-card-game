# 《弈者》玩法介绍（当前版本锚点）

> 本文记录当前可玩版本的规则锚点。产品决定可以改变本文；确认改动时，必须同时更新实现与测试，不能把本文当成不可变的历史设定。

## 状态标记

- **已实现**：当前 Run、BattleController 和 Godot UI 可以实际走通的规则。
- **已确认、待实现**：产品已确认，代码尚未接入。
- **候选提案**：尚未确认，不进入卡池、存档、平衡或 UI 承诺。
- **实现缺口**：目录或旧文案已有承诺，但当前入口未实现该效果；不得当作可用能力推导平衡。

当前不开放神通决策面板；`charge`、`assault`、`sacrifice` 及其两件进化遗物仍为休眠内容，不接入 Run 或战斗输入。

## 目标

单局目标是让四名弟子、弈者牌组和遗物穿过三章地图，并击败第三章 Boss。每场战斗的直接目标是消灭对方全部能维持战局的棋子；弈者负责把卡牌、能量和持续成长转化为棋盘优势，而棋子负责占位与攻击。

## 已实现：Run 循环

1. 新局从 **3 名**非命轮弈者中选 1 名，候选保证至少有一名永久成长型弈者。开局取得两种不同的零费自由技，各一张。
2. 每章地图为三行十列；玩家沿可达节点前进。节点包括普通战斗、精英、Boss、商店、锻造和事件。
3. 战斗胜利结算货币、奖励、棋子生命比例与合法永久成长；战斗失败不提交本场成长。第三章 Boss 胜利为 `cleared`，战斗失败为 `failed`。

新局初始货币为 **30**。当前章节奖励配置为：普通战斗 `15` 货币，候选为`3`个遗物；精英 `25` 货币，候选为`2`张卡牌和`1`个遗物；Boss `40` 货币，候选为`1`张卡牌和`2`个遗物。卡牌候选混合自由技与当前上阵弈者解锁的专属牌。货币与候选奖励分别结算，候选中只选一项。实际候选由节点、已持有内容和权威快照限制。

### 四人阵型与库存

Run 保留六个位置，但新局只有四名弟子：

| 槽位 | 默认状态 |
|---:|---|
| 1 | 空 |
| 2 | 甲卒（唯一默认前排） |
| 3 | 空 |
| 4 | 死士 |
| 5 | 机弩 |
| 6 | 旗兵 |

- 空位是未占用位置，不是生命为 0 的阵亡棋子，不能被治疗或成长激活。
- 地图“调整阵容”允许四名既有弟子换位，或替换已占用位置的兵种；库存不能拖进空位新增第五、第六名弟子。
- 甲卒、死士、机弩、旗兵各有 **2** 份默认库存。历史六满存档可保留旧三甲卒，但换出后不能再超额加入。

## 已实现：战斗与卡牌

### 手牌、技能点与能量

- 战斗基础SP为 **10/10**，回合恢复 **1 SP**，上限与额外收益可被实际生效的遗物改变。
- 手牌上限 **7**；开场与每个非终局回合均按 `2 + N` 抽牌，`N` 为当前上阵弈者数。抽牌堆空时洗回弃牌堆。
- 弈者部署与弟子阵位是两套数据。当前弈者部署最多6个唯一槽位；四名初始弟子不意味着四名初始弈者，也不能按弟子数量计算抽牌。
- 牌库由自由技多重集、上阵弈者的主动专属技和运行中生成的大招构成。骑士专属为被动：不生成专属牌，但仍计入 `N`。
- 自由技成功释放后，全体上阵弈者获得 `5 + 实际消耗SP × 5` 能量；专属技成功释放后，所属弈者获得 `10 + 实际消耗SP × 10` 能量。免除费用时按实际0消耗计算，不能按卡面基础费用计算。
- 自由技与通常专属技成功使用后弃置；**影狩初始专属“潜影”成功结算后回到手牌，保留同一实例**，仍受SP与潜行目标条件限制。大招成功使用后消耗。回合结束时剩余手牌（含潜影）清理至弃牌堆，不保留整手到下一回合。
- 自由技、专属技、大招都是可拖拽的卡牌。上拖提交给既有领域目标解析；当前没有 HTML 原型式手动点目标玩法。
- 能量达到弈者上限时，本次能量清零并生成一张该弈者大招；手牌已满则将大招置于抽牌堆顶。单次跨多个阈值只生成一次。
- 弈者能量以头像周围的环形进度显示，悬停头像查看当前值与上限；不再单列能量条。环形进度跟随真实能量，生成大招后随能量清零。
- 正在播放上一张牌时，仍可拖出其他可用牌进入结束回合按钮上方的等待队列。等待牌尚未向领域提交、不提前扣SP；轮到它时重新校验并解析目标。等待项可取消，失效则退回；同一实例不能重复排队。
- 首次入队从实际释放位置平滑移入对应预览/牌签。队列未清空时不能结束回合，暂停与终局按各自规则冻结/清空。此展示规则不改变底层单卡顺序结算。

### 一回合的攻击段

当前开发版提供战斗快捷键 **X**：在进行中的、未暂停战斗里直接判胜，沿用正常胜利结算与Run奖励/成长写回。不会伪造逐个击杀或修改双方生命；已经结束的战斗不能重复触发。此快捷键用于快速验证，不改变普通战斗胜负条件。

1. 玩家在 `player_input` 阶段打牌或结束回合。
2. 敌方弈者按敌方列表顺序，以既有敌方 AI、SP 与能量规则行动。
3. 棋子按槽位依次结算“我方棋子 → 敌方棋子”；额外行动、追击、反击和兵种效果在各自攻击链中触发。
4. 结算灼烧、临时状态衰减、回合资源恢复和下一回合抽牌；终局不再抽牌。

同一次攻击中的单段群攻同时展示各目标伤害；宁不凡大招每一击为独立一段，逐段展示。反击与追击保持独立动作。暴击、格挡同时发生时只显示一个实际伤害数字，附“暴击·格挡”；完全格挡显示0。

目标选择、格挡、暴击、灼烧、傀儡及具体伤害数值以战斗目录与效果实现为准；旧版本数值长表不是当前权威来源。

### 英雄与跨战斗成长

内容目录有 9 名玩家弈者；命轮不进入 Run 初始/招募候选，因此可选池为 **8 名**。主动专属会入牌库，每名弈者的大招由能量满时生成。

已落地的 Run 永久成长包括元帅的将军成长、炎术士的引火投资和宁不凡的拳意；它们经 `permanent_buffs` 与战斗进度快照，在胜利后写回 Run。其余战斗内状态仅按各自实际效果持续。

| 可选弈者 | 专属技与核心职责 | 大招方向 |
|---|---|---|
| 赤焰 | 蔓炎扩大已有灼烧，基础消耗按场内次数1/2/4/8递增 | 利用目标灼烧层数造成群体单段伤害 |
| 元帅 | 2SP封命，将军及所在弟子位置的永久成长 | 治疗将军并给予出征 |
| 骑士 | 被动反击，不产生专属卡 | 强化超级反击窗口 |
| 炎术士 | Run每场至多一次引火投资，基础消耗按投资次数2/3/4封顶 | 炎汲续航 |
| 宁不凡 | 1SP拳劲，战内叠拳势、Run叠永久拳意 | 逐段攻击，击杀追加段数并转火 |
| 沉戈 | 1SP破势，对敌方建立标记 | 全体破势与破阵领域 |
| 千机 | 1SP机巧造物，在可召唤位置生成傀儡 | 补充傀儡并启用殉道 |
| 影狩 | 1SP潜影，赋予非傀儡潜行并改变后续锁定 | 点杀与潜行单位追击 |

拳势与永久拳意不是同一项：拳势战斗内从0累积、上限5；永久拳意随Run保存，每层提供5%拳系伤害成长，每5层增加1段大招基础段数。英雄自身计数应显示在对应弈者状态栏，棋子的附魔、破势等显示在棋子状态栏，阵营效果另列，不混成一个总层数。

弈者状态按实际生效项动态排列为名称与层数标签，悬停查看说明。不显示零层拳势或未启用状态，也不为各弈者固定预留专属进度；消失的状态释放位置，多个状态自动换行。永久成长、战内拳势及本场技能使用状态分别呈现。

### 已实现：弈者专属牌池扩展（2026-09-09）

- **初始专属**：选择、招募并上阵主动专属弈者后，战斗牌库获得该弈者初始专属一张。重复进入战斗不累计赠送；骑士被动仍不生成初始专属。
- **获取候选池**：当前上阵弈者解锁其初始主动专属和已定义的后续专属，参与战后/商店的卡牌候选；解锁不等于自动获得全部牌。大招仍只由能量生成，不进该候选池。
- **副本**：奖励、购买获得的额外专属副本独立持有，不混入自由技ID列表；每份在战斗中成为独立卡牌实例。重复副本不会增加上阵弈者数N。
- **归属**：后续专属以对应弈者为施法者，只给予该弈者专属技能量收益，不使用自由技的全体能量规则。
- **首张后续专属：沉戈·乘隙**，1SP。敌方存在存活破势单位时，我方攻击最高的存活非傀儡获得2层追击；攻击相同按槽位、单位ID稳定选择。立即增加追击层数，不立即发动攻击，也不强制追击命中破势目标。条件失效则不可出牌，不扣SP。

### 当前自由技池：定义与实际状态

目前10种自由技可进入玩家构筑，允许重复副本。Run新局只从零费池取两种不同的牌；当前即小回血和灼痕标记，不使用角色目录中的旧初始自由技配置。

| 自由技 | 基础SP | 规则摘要与当前状态 |
|---|---:|---|
| 基础叠层 | 1 | 敌方全体各1层灼烧，每目标30%概率额外1层 |
| 灼烧引爆 | 2 | 引爆灼烧最多的可锁定敌人，每层5伤害并清层，击杀后分配原灼烧 |
| 斩杀 | 2 | 最高攻击我方棋子对低生命敌人造成150%直接伤害，击杀返1SP |
| 棋子行动 | 1 | 最高攻击我方棋子获得一次额外行动；当前不是手动指定棋子 |
| 棋子格挡 | 1 | **实现缺口**：能赋予临时格挡状态，目录承诺+15%，正式回调未应用加成 |
| 棋子增伤 | 1 | **实现缺口**：能赋予增伤状态，tuning为25%、旧文案30%，正式回调未应用加成 |
| 棋子回血 | 1 | 全体存活我方棋子各回复5%最大生命 |
| 小回血 | 0 | 当前生命比例最低的存活我方棋子回复5%最大生命 |
| 灼痕标记 | 0 | 灼烧最多的可锁定敌人增加1层灼烧 |
| 血移 | 1 | **实现缺口**：最高生命者得到易伤，其余得到庇护；状态存在，但承伤倍率未接入 |

设计新自由技时不能把“目录存在”当成“机制已生效”。候选牌的完整设计另见下方提案链接。

### 敌方弈者按层数

Run 复用已有军令、铁卫、千机定义的专属技、技能池和能量上限：

| 章节 | 敌方弈者 |
|---:|---|
| 1 | 敌·军令（101） |
| 2 | 敌·军令（101）、敌·铁卫（102） |
| 3 | 敌·军令（101）、敌·铁卫（102）、敌·千机（103） |

普通、精英和 Boss 均按当前 Run chapter 生效。此规则只用于带 Run progress 的启动配置；M4 直开仍使用所选 stage 的原始完整敌方 roster。

## 已实现：遗物、经济与保存

- 遗物目录有 22 个定义；两件神通进化遗物依赖休眠神通，已从实际 Run 候选过滤。因此当前可获得池为 **20 件**有效遗物，包含通用、兵种强化和精英来源内容。
- 商店提供自由技、已解锁专属牌与遗物候选；锻造提供兵种强化遗物并可治疗。价格、折扣和可出售自由技由章节、遗物持有状态和权威 option snapshot 判定，UI 不自行计算。本轮未开放额外专属副本出售。
- 自由技按允许重复的 ID 多重集保存；购买、奖励、出售都按一份副本处理。`basicDamage` 保留底层 handler，不进入玩家牌库、商店或奖励。
- Run 在创建、成功的安全状态变更和进入节点前保存 checkpoint。打开中的战斗进度对象不直接存档，节点启动前保存可恢复的地图状态。
- checkpoint 保存 Run 状态、随机源及奖励/商店 authority；恢复时验证结构、内容引用和历史兼容迁移。篡改的候选或 authority 会被拒绝。

## 已确认、待实现与候选

### 已确认的实现缺口（2026-09-09核对）

`BattleBootstrap` 为正式伤害管线注入的 `get_damage_multiplier` 固定返回1，`get_block_rate` 只读单位基础格挡。`pieceDamageUp`、`tempBlock`、`bloodShiftVulnerable/Guard` 以及 `vexed` 没有在该路径被用于对应伤害/格挡修正。因此困扰虽然可挂上，也不会降低实际伤害。这与原有文案承诺不同。

本轮记录该缺口，不借文档修改暗中改变战斗数学。后续修复应以实际同条件伤害/格挡对照测试证明生效，再移出本节；同时统一棋子增伤的25%配置和30%文案。新自由技若依赖这些机制，须先完成接线，不能只新增状态名。

| 状态 | 内容 | 说明 |
|---|---|---|
| 候选 | [自由技扩充提案·第一批](自由技扩充提案-第一批.md) | 尚未实现；不进入当前卡池、商店、奖励或平衡承诺。 |
| 实现缺口 | 上述增伤、格挡、血移与困扰计算 | 不是新玩法提案，是已挂状态未生效的行为差异；修复后补对照测试。 |

## 决策记录与同步流程

1. 用户的新玩法决定优先于本文和 `AGENTS.md` 的历史边界；确认后可直接修订锚点。
2. 改规则时同步更新：本文件、`AGENTS.md` 简要边界、相关实现与测试。
3. 若代码与本文不一致，先用测试和实际入口核对，再按已确认产品意图修代码或本文；不能静默沿用旧文案。
4. 未确认的设计保持候选状态；确认后标为待实现，待实现、存档语义和测试都落地后才标为已实现。
