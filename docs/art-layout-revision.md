# 战斗界面美术修改要求（第一期：布局）

## 依据与范围

- 依据现状：`scenes/battle/battle_screen.tscn` 及其子场景，证据截图 `tests/artifacts/m4/01~06`。
- 本期只处理**布局与信息结构**；色板、字体、立绘、FX 强度留到第二期，避免一次性改动无法定位回归。
- 不改动 Controller/VM/事件合同，不改动 `BattlePresentationQueue` 时钟与忙锁；所有条目都只落在 `ui/` 与 `scenes/` 层。
- 完成判定统一用 1200×700 截图 + 两档非默认窗口尺寸截图，见文末「验收产物」。

## 现状的根因（不是逐条像素问题）

1. **整屏是绝对坐标拼出来的**。`battle_screen.tscn` 里 HUD / Arena / CombatLog / HandReserve 全部 `layout_mode = 0` + 手写 offset，Arena 内部的标题、棋盘、弈者面板同样是手写 offset。而 `project.godot` 是 `stretch/mode="canvas_items"` + `aspect="expand"`，任何非 1200×700 的窗口都只会拉出留白或裁切，不会重排。
2. **右侧两栏是"先占位、再填内容"**。战斗日志固定 306×330、弈者面板固定 194×150×2，实际内容常常只有 2 行日志、1 名弈者，于是右半屏长期空着（见 01 截图），而左侧棋盘和手牌反而挤。
3. **手牌区是固定预留区**。`HandReserve` 是一块 1160×248 的实心 Panel，手牌为空时它就是一个大空框（见 06 截图），手牌满时卡片又从它的上沿溢出去压住 Arena（见 01/02 截图）——框既框不住内容，又在没内容时占着屏。

先修这三条，大部分"不自然"会自己消失。

## P0 · 骨架重构（本期主线）

### A1 根布局容器化

- `BattleScreen` 改为 `MarginContainer(边距 16) → VBoxContainer(separation 12)`，三段：`TopBar` / `MainRow` / `HandLayer`。
- `MainRow` 用 `HBoxContainer`：`战场区(size_flags_horizontal = EXPAND_FILL)` + `日志抽屉(定宽 300，可隐藏)`。
- 删除 `BattleScreen`、`Arena` 内所有手写 offset，改用容器 + `custom_minimum_size` + `size_flags`。
- `HandLayer` 用一个覆盖在 `MainRow` 下缘的 `Control`（`mouse_filter = PASS`），不参与 VBox 高度分配，这样手牌上浮不再挤压战场。
- 验证口径：窗口分别设 1200×700 / 1280×720 / 1600×900，三张截图均无溢出、无空洞、无控件被裁。

### A2 战斗日志：默认隐藏，按键唤起 ← 用户明确要求

- 默认状态：**完全隐藏**，不占 `MainRow` 宽度（不是 `modulate.a = 0`，是从布局里退出），战场区自动吃掉这 300px。
- 唤起方式（两条都要有）：
  - 新增 InputMap action `toggle_combat_log`，主键 `Tab`，备用键 `L`；在 `battle_screen.gd` 的 `_unhandled_input` 里响应，避免和卡牌拖拽抢输入。
  - HUD 右侧加一个「日志」按钮，与快捷键同一入口函数，按钮保持按下态反映抽屉开合。
- 表现：从右侧滑入/滑出，0.18s，`Tween.EASE_OUT`；开合期间不阻塞表现队列，也不锁输入。
- 未读提示：抽屉关闭期间新增日志条目时，HUD 日志按钮显示未读角标（数字，上限 `99+`），打开即清零。
- 打开态宽度 300，最小高度跟随 `MainRow`；条目从下往上追加并自动滚到底。
- 终局/fatal 时不要强制弹开日志，保持用户当前开合状态。

### A3 手牌区：去掉固定底板

- 删除 `HandReserve` 这块 Panel 底板。手牌直接放在 `HandLayer` 上，背景改为屏幕底部一层自上而下的渐隐暗色（`gradient`，高度约 200，`mouse_filter = IGNORE`），只做视觉压底，不画边框。
- 手牌数为 0 时，底部不得出现任何可见框体（当前 06 截图那块空矩形必须消失）。
- 手牌层 z 序高于战场，低于结果层/fatal 层/日志抽屉。

### A4 手牌排布：解决重叠遮挡与上溢

现状 `hand_view.gd`：卡宽 168，`preferred_card_spacing = 126` → 相邻卡重叠 42px，且后加入的卡压在前一张之上，导致左起 6 张的卡名与描述被压掉一半（01 截图）。

- 卡面尺寸由 168×224 降为 **150×210**（`card_view.tscn` 的 `custom_minimum_size` 与内部 offset 同步等比调整）。
- 扇形排布约束：
  - 7 张时整排总宽 ≤ 1000，居中；
  - 相邻间距下限 = 卡宽 × 0.72（约 108），低于该值不再继续压缩，改为整体缩放；
  - 重叠时统一 **左压右**（`move_child` 顺序反转），保证每张卡的左侧 108px 始终完整可见；
  - 卡名、费用、类别必须落在这左侧安全区或卡片顶部 56px 内，任何遮挡状态下都可读。
- 上溢约束：`baseline_y + arc_height` 之后的**旋转外接框**顶边不得越过手牌层上界（当前外侧卡片顶部已侵入 Arena）。已有的四角断言测试保留并把上界一起纳入。
- hover：允许抬升并覆盖战场，但抬升的卡必须整张可读（`scale 1.08` + 上移 28 + 投影 + 置顶），且抬升不改变其余卡片的位置（当前 02 截图里 hover 卡把邻卡挤歪）。

### A5 弈者面板并入各自棋盘，取消"第三栏"

- 现状：`AllyHeroes` / `EnemyHeroes` 是 Arena 右侧一根独立竖栏，固定 194×150×2，我方只有 1 名弈者时下方大片空白（01 截图）。
- 要求：把弈者条**贴到各自棋盘的正上方**（我方弈者压我方棋盘顶、敌方弈者压敌方棋盘顶），与棋盘同宽，高度随人数自适应（`VBoxContainer` + 无固定 `custom_minimum_size`）。
- 这样 `MainRow` 只剩「我方列 / 敌方列 / 日志抽屉」，日志关闭时就是干净的左右对称双列。
- 敌方弈者当前是灰色占位块（`PortraitPlaceholder`），补图前保留占位，但占位框尺寸/圆角/描边必须与有立绘的一致，不能一个是方块一个是满铺贴图。

### A6 Arena 与棋盘的余白统一

- 棋盘底边到 Arena 底边现有约 30px 的残留空隙，是 offset 手算的副产品；容器化后由 `separation` 统一，不允许再出现单侧不对称的死空隙。
- 我方/敌方两块棋盘的标题、外框、内边距必须完全镜像一致，只有主色不同。

## P1 · 组件级信息结构（本期一并做，改动小）

### B1 棋子格 `piece_slot.tscn`

- `guard / warrior / archer` 是英文原始 key，正式界面必须走本地化名（守卫 / 战士 / 射手）。
- `无 Buff` 空态占位删除：无 buff 时该行隐藏，不留空行。
- `存活 / 已阵亡` 不再占一行文字：存活态不显示任何状态字，阵亡态整格置灰 + 斜杠/裂纹标记 + 名称加删除线。
- HP：数字叠在血条上（居右），不再是「条 + 独立数字」两个控件横排。
- 结果：每格从现在的 4 行压到 2 行，格子高度可从 76 降到 ~64，棋盘整体更紧。

### B2 卡牌 `card_view.tscn`

- 底部 `InstanceId`（当前显示「战斗卡牌」）是调试残留，正式界面移除。
- 描述文本被截断（截图里显示「同一 1200×700 窗…」）：`autowrap` 已开但高度不够，描述区按 3 行预算重排，超出用省略号 + hover 展开完整文本。
- 费用底框 `corner_radius = 18` 配 38×38 的方框不是正圆，改为 `radius = 半边长` 或直接换圆形节点。
- `公共` / `弃牌` 两个标签挤在同一行左右两端且贴边，统一为底部一行的 tag 组。

### B3 顶栏 HUD `battle_hud.tscn`

- 现状：左侧四段信息挤成一串，中间约 500px 纯空白，右侧 7 个控件排一条。
- 改为三组，组内紧凑、组间留白：
  - **左**：回合、SP（SP 用条 + 数字，不只是文字）。
  - **中**：牌堆 抽/手/弃/耗，四个图标 + 数字，不再是一整句文本。
  - **右**：倍速段控件、自动开关、日志按钮（A2）、结束回合。
- `SpeedLabel`（那个「1x」）与四个倍速按钮的选中态重复表达同一件事，删掉 `SpeedLabel`，只保留段控件高亮。
- `结束回合` 是主操作，必须是全屏唯一的高对比主按钮，尺寸不小于 120×44。

### B4 标题与调试字样

- `我方棋盘 2×3` / `敌方棋盘 2×3` 里的 `2×3` 是规格调试信息，正式界面去掉，只留「我方 / 敌方」。

### B5 结果层 `battle_result_overlay.tscn`

- 现状文字与按钮直接浮在暗底上，按钮无可见边界（06 截图），像没做完。
- 要求：加一块居中结果卡片（面板 + 描边 + 投影），标题 / 原因 / 主按钮三段式；`重新开始演示战斗` 用与 `结束回合` 同一套主按钮样式。
- `fatal_overlay` 同一套版式，只换主色与图标。
